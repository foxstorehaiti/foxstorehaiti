2.2. Principes d'Architecture

· Autonomie des pages : Chaque page HTML contient l'intégralité de ses styles (CSS) et de ses scripts (JavaScript) en interne. Cela garantit une indépendance totale et facilite les modifications sans risque de régression.
· Chemins absolus : Toutes les ressources sont référencées avec des chemins absolus commençant par / (ex : /assets/freefire-logo.png, /gaming/freefire.html), assurant un fonctionnement correct quel que soit le niveau de profondeur.
· Séparation des préoccupations : La structure du projet sépare clairement les différentes fonctionnalités (authentification, produits, paiement, commandes, etc.), rendant le code maintenable et évolutif.
· Approche PWA : Le projet inclut un manifest.json et un service-worker.js, permettant une installation sur mobile et un fonctionnement en mode hors ligne partiel.

3.3. Règles de Codage

1. Autonomie des pages : Chaque fichier HTML contient son propre CSS dans une balise <style> dans le <head> et son propre JavaScript dans une balise <script> en fin de <body>. Aucune dépendance externe autre que Font Awesome 6, Google Fonts et Firebase.
2. Absence d'émojis : Aucun caractère Unicode émoji n'est utilisé dans le code ou le contenu. Toutes les icônes proviennent exclusivement de Font Awesome 6.
3. Chemins absolus : Toutes les ressources sont référencées avec des chemins absolus commençant par / (ex : /assets/freefire-logo.png, /gaming/freefire.html).
4. Images carrées : Tous les logos sont carrés et utilisent object-fit: contain et aspect-ratio: 1/1. Dimensions : 160×160 px pour les logos produits, 40×40 px pour les moyens de paiement.
5. Code indenté et commenté : Le code est proprement indenté et commenté en créole pour faciliter la maintenance.
6. Prêt pour la production : Aucune donnée simulée ni placeholder. Toutes les fonctionnalités sont opérationnelles.
